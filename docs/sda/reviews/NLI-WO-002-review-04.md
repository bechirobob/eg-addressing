## 4. Open findings

### NLI-WO-002-F02 — Transformation registry remains fallback-driven and semantically unsafe

**Class:** BLOCKER  
**Affected criteria:** AC-01, AC-06, AC-11, AC-12, AC-16, AC-17  
**Observation:** Live catalog discovery is now valid, but `map_target_for()` contains a small explicit map followed by broad field-name rules for IDs, statuses, geometry, names, codes, timestamps, notes and all remaining fields. The generated registry therefore remains heuristic rather than hand-reviewed.

Concrete examples at the reviewed head include:

- `address_corrections.correction_type` is sent to the governed raw archive instead of `correction_case.correction_type`;
- `address_corrections.status` maps to `migration_exception.exception_type`, not the target case lifecycle;
- `address_corrections.note` and `reviewer_note` become formal exceptions whose target is only a migration-exception ID, while `value_preservation` still says “copy typed value” without a governed value location;
- ID references such as `address_corrections.address_id` map only to `legacy_crosswalk.legacy_id`, without identifying the referenced canonical record/crosswalk lookup;
- coordinate fields are independently described as creating the same geometry, rather than one grouped transformation with one source record and validation rule.

The checker validates target-field existence and required metadata strings, not transformation meaning, type compatibility, grouping, authority, reconstructability or expected values.  
**Risk/consequence:** WO-002B could pass design CI while losing case meaning, creating ambiguous crosswalks, duplicating geometry, or representing migration exceptions as canonical data.  
**Required resolution:** Replace fallback logic with a reviewed transformation registry checked into source. Each row or grouped transform must define source record key, related source fields, exact target rows/fields, generated target IDs, crosswalk joins, value map, archive object, authority/RFI, expected-value examples, validation SQL, and exception path. The pipeline must fail when a current field is handled by a generic fallback or a formal exception without a named owner and governed raw-value reference.

### NLI-WO-002-F03 — Vocabulary and administrative-code authorities remain contradictory

**Class:** BLOCKER  
**Affected criteria:** AC-03, AC-07, AC-12–AC-14, AC-20  
**Observation:** Review 04 adds separate vocabularies, but they are not consistently assigned. For example, `source_authority.status` still references the old generic `lifecycle_state` vocabulary rather than `source_authority_lifecycle`; release fields continue using the pre-existing release vocabulary while a second `publication_lifecycle` vocabulary is generated. The schema retains `administrative_unit.stable_code` while also introducing effective-dated `administrative_code_history.official_code`, leaving two code authorities.  
**Risk/consequence:** Two services can implement different legal code histories or source/publication lifecycles while both comply with different parts of the pack.  
**Required resolution:** Remove or explicitly derive every duplicate authority. Assign each stateful field exactly one entity-specific vocabulary. Define the identity/code relationship, current-code projection and historical-code lookup, then reconcile typed metadata, SQL, dictionary, mapping, state machines and fixtures.

### NLI-WO-002-F04 — Subject, name, object-link, dispute and cardinality integrity is not physically connected

**Class:** ARCHITECTURE DECISION REQUIRED  
**Affected criteria:** AC-02–AC-05, AC-10, AC-14, AC-20, AC-21  
**Observation:** A `registry_subject` table was added, but existing polymorphic fields do not reference it and the target SQL defines no subject-registration trigger or integrity function. `name_record`, `location_record_object_link`, `dispute_case` and `geometry_version` can therefore point to arbitrary entity/ID pairs. The record-type/object-role cardinality matrix is not emitted as database constraints or complete trigger logic.  
**Risk/consequence:** Orphaned names, disputes, geometry and primary-object links can be inserted; multiple primary subjects or invalid roles can pass validation.  
**Required resolution:** Select and fully implement in the design either typed link tables or a subject-registry contract. Provide non-executable but runnable trigger/function definitions for registration, referential validation, update/delete behavior, permitted roles, record-type cardinalities and one-current official-name rules. Add positive and negative fixture tests.

### NLI-WO-002-F05 — Temporal intervals and predecessor/successor chains remain under-constrained

**Class:** BLOCKER  
**Affected criteria:** AC-07, AC-08, AC-14, AC-20  
**Observation:** The target SQL checks `from < to` and creates partial one-current indexes. It does not prevent overlapping effective or recorded intervals, enforce same-record predecessor/successor links, require reciprocal links, prevent cycles/self-links, or constrain object-link periods to their record-version periods. Many mutable authoritative objects retain effective dates without recorded-time versions.  
**Risk/consequence:** Multiple conflicting official histories or self/cyclic supersession chains can satisfy the schema.  
**Required resolution:** Specify and render range/exclusion constraints or complete trigger logic for every temporal authority. Add reciprocal/same-owner/no-cycle/no-self rules for version, alias, record and geometry chains. Define recorded-time strategy for every mutable authoritative entity and validate backdated correction scenarios.

### NLI-WO-002-F06 — Geometry subject and promotion integrity remains unproved

**Class:** BLOCKER  
**Affected criteria:** AC-09, AC-11, AC-14, AC-20  
**Observation:** The disposable schema correctly enforces SRID/validity and a geometry-role/type trigger for approved geometry. It does not enforce `subject_entity/subject_id` existence or the role-to-subject registry, and the observation table is not subject to equivalent role/type rules. The generic fixture uses an arbitrary subject string and a self-referencing supersession and still inserts successfully.  
**Risk/consequence:** Orphaned or semantically wrong geometry can become current canonical geometry while all current checks pass.  
**Required resolution:** Connect geometry to the accepted subject-integrity strategy; enforce role-to-subject and role-to-type rules for observations and versions; prohibit self/cyclic supersession; define promotion decision requirements and interval consistency; add negative tests for wrong subject, wrong type, wrong SRID, invalid geometry, duplicate current geometry and unauthorized promotion.

### NLI-WO-002-F07 — Generated lifecycle graphs encode invalid government workflows

**Class:** BLOCKER  
**Affected criteria:** AC-07, AC-13, AC-14  
**Observation:** `render_vocab_and_lifecycle()` creates transitions by walking vocabulary values in their stored order. This produces invalid paths such as:

- canonical `superseded -> disputed` and `retired -> revoked`;
- case `approved -> rejected` and `rejected -> resolved`;
- geometry `rejected -> reviewed` and `superseded -> valid-with-warning`;
- publication `approved -> draft`;
- intake `closed -> duplicate-review` and `promoted-to-canonical -> rejected`;
- field workflows that advance from cancelled states into evidence states.

The generated table uses generic events, evidence and visibility instead of actual authority rules.  
**Risk/consequence:** Service and database implementations would permit invalid decisions and block valid correction/review paths.  
**Required resolution:** Hand-author transition registries for each lifecycle. Validate allowed edges, terminality, reachability, actor/permission/scope, authority, evidence, effective/recorded time, audit event, public behavior, appeal/reversal and invalid-transition handling in CI.

### NLI-WO-002-F08 — OpenAPI inventory is not a reliable policy or response-projection map

**Class:** BLOCKER  
**Affected criteria:** AC-10–AC-12, AC-15  
**Observation:** OpenAPI generation is real, but authorization is inferred by scanning up to 80 source lines after each function. This demonstrably misclassifies the public root endpoint as authenticated/admin even though its function contains no authentication. Many successful responses have no OpenAPI fields because handlers return untyped dictionaries; the generated matrix therefore does not map actual response fields to target projections. Field classification remains keyword-based.  
**Risk/consequence:** Protected/public boundaries and breaking response changes can be recorded incorrectly while the operation count remains complete.  
**Required resolution:** Introduce an explicit route-policy registry or introspect FastAPI dependency callables without source-window leakage. For dynamic responses, add controlled response-contract inventories or response models sufficient to enumerate fields. Map every request/response/error field to classification, target projection, release prerequisite, compatibility, adapter/deprecation and tests.

### NLI-WO-002-F09 — Convergence and scale plans remain generated summaries

**Class:** REQUIRED  
**Affected criteria:** AC-17, AC-19  
**Observation:** The convergence plan groups transformations by primary target, shows only a truncated sample of current fields per row, and repeats generic idempotency, tolerance, compatibility and cutover language. The declared 0.1% exception threshold, application version names, national volumes/QPS and storage estimates are not tied to measured data, an owner-approved hypothesis, or a capacity calculation.  
**Risk/consequence:** The implementation work order cannot be safely decomposed, estimated, performance-tested or approved for cutover.  
**Required resolution:** Derive named migration units from the corrected transformation registry. Include all source fields/transforms, dependencies, crosswalk/exception schema, write owner, application-version matrix, idempotency, conflict precedence, validation SQL/tolerance, backup/forward-recovery boundary, monitoring window, cutover/abort gate and retirement proof. Label scale assumptions with source, confidence range, horizon and required owner approval.

### NLI-WO-002-F10 — The seven machine-readable scenarios are identical and only one is executed

**Class:** BLOCKER  
**Affected criteria:** AC-05, AC-08–AC-11, AC-18, AC-20  
**Observation:** `generate_fixtures()` creates one generic `records` dictionary and assigns it to all seven scenario names. `execute_target_schema_and_fixtures()` then loads only `next(iter(fixtures['scenarios'].values()))`. The reported 45 inserted rows are one generic row per entity, not seven scenario validations. The fixture contains semantically invalid values—such as a root administrative version parented to itself, arbitrary geometry subjects and self-supersession—which pass because the required semantic constraints do not exist.  
**Risk/consequence:** Urban, rural, no-road, multi-unit, correction, dispute and boundary-change behavior remains untested despite a green fixture report.  
**Required resolution:** Create independently authored scenario datasets. Execute every scenario in an isolated transaction/schema, validate every non-null/FK/vocabulary/interval/cardinality/geometry/publication rule, and include expected negative cases. Render the scenario documents and exact public/operator projections from those validated fixtures.

### NLI-WO-002-F11 — ADRs remain template-generated rather than authoritative decisions

**Class:** ARCHITECTURE DECISION REQUIRED  
**Affected criteria:** AC-06, AC-08, AC-09, AC-21  
**Observation:** ADRs now contain more useful alternatives, but `render_adrs()` still emits all five from one shared template with identical drivers, privacy language, operational trade-offs, migration consequences and failure modes. Domain-specific alternatives are short labels rather than substantive analysis.  
**Risk/consequence:** WO-002B implementers can reinterpret key identifier, hierarchy, object, temporal and geometry decisions because trade-offs and boundaries are not sufficiently explicit.  
**Required resolution:** Hand-author ADRs 005–009. For each, document decision-specific context, alternatives, security/privacy, performance, offline/field implications, operational support, migration impact, failure modes, consequences, acceptance tests, supersession and unresolved institutional RFIs.

### NLI-WO-002-F12 — CI proves execution and field counts, not the semantic claims in its PASS report

**Class:** BLOCKER  
**Affected criteria:** AC-01, AC-03–AC-21  
**Observation:** PostGIS execution is genuine. Nevertheless:

- target catalog comparison checks missing/extra columns but not every metadata type, default, FK, check, index and trigger;
- most free-form `constraints` metadata is not rendered by `render_target_sql()`;
- transformation validation checks target-name existence rather than expected source/target values;
- lifecycle validation checks vocabulary presence rather than legal transition graphs;
- fixture validation counts one inserted row per entity and only confirms each scenario contains entity keys;
- the semantic report says scenarios and mappings are validated although the defects above pass.

**Risk/consequence:** A syntactically executable but architecturally invalid model receives a green government-design signal.  
**Required resolution:** Make reports state only checks performed. Add metadata-to-catalog parity for types/defaults/nullability/FKs/checks/indexes/triggers; negative constraint tests; transformation expected-value tests; lifecycle graph validation; per-scenario fixture execution; subject/cardinality/temporal/geometry/publication assertions; and response-contract projection validation.
