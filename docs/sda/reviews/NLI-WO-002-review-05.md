## 4. Open findings

### NLI-WO-002-F02 — The reviewed transformation source is complete by row count, not by semantic decision

**Class:** BLOCKER  
**Affected criteria:** AC-01, AC-06, AC-11, AC-12, AC-16, AC-17

**Observation:** `transformation-registry-reviewed.json` is now required and unknown current fields fail CI, which is positive. Its contents still show bulk-stamped approval rather than resolved field decisions:

- `address_corrections.correction_type` is archived to `source_payload_archive.payload_uri` rather than translated to `correction_case.correction_type`;
- `address_corrections.note`, `reviewer_note`, and `reporter_name` are formal exceptions targeting only `migration_exception.migration_exception_id`, while their `value_preservation` says “copy typed value” and provides no archive row/object target;
- many `source_row_key` values are the field being transformed rather than the table's stable row key;
- ID references map only to `legacy_crosswalk.legacy_id` without defining the referenced canonical entity lookup or crosswalk join;
- coordinate and accuracy fields remain separate rows claiming to create the same geometry rather than one grouped transform with one output row and one validation result;
- most rows share identical review notes, reviewer label, exception text, compatibility period, retirement condition, and generic count-based validation.

**Risk/consequence:** A future WO-002B implementation can satisfy registry coverage while losing case meaning, duplicating geometry, misjoining references, and treating unresolved values as accepted review decisions.

**Required resolution:** Replace bulk approval with a genuinely reviewed transformation source. Use stable source row keys, grouped transforms, exact target rows/fields, canonical ID and crosswalk joins, controlled value maps, archive object/value references, example input/output values, executable validation queries, and explicit authority/RFI status. A formal exception must identify both the exception row and the governed location of the original value. Add semantic tests for every non-trivial transform class and fail CI on boilerplate or unresolved rows marked approved.

**Disposition:** OPEN

### NLI-WO-002-F03 — Lifecycle assignment is overwritten after entity-specific correction

**Class:** BLOCKER  
**Affected criteria:** AC-03, AC-07, AC-12–AC-14, AC-20

**Observation:** `load_and_correct_model()` first assigns dedicated vocabularies such as `building_lifecycle`, `road_lifecycle`, `unit_lifecycle`, and `locality_lifecycle`. A later compatibility block reassigns the same `lifecycle_state` fields for country, road, road segment, building, entrance, unit, landmark, non-building object, and locality to generic `reference_object_lifecycle`. The final model therefore contains fields whose definitions say “entity-specific lifecycle” but whose vocabulary is generic—for example `building.lifecycle_state`.

The checker verifies only a selected subset of field-to-vocabulary assignments, so this contradiction remains green.

**Risk/consequence:** Workflow code, database checks, analytics, and migrations can use a dedicated graph while the stored field is constrained by a different vocabulary.

**Required resolution:** Remove the later generic reassignment block. Establish one authoritative field-to-vocabulary registry and assert every stateful field against it in CI. Remove or explicitly deprecate obsolete generic lifecycle vocabularies. Regenerate and verify SQL FKs, dictionary, lifecycle tables, mappings, fixtures, and API projections from the corrected assignments.

**Disposition:** OPEN

### NLI-WO-002-F04 — The subject registry does not prove native target identity or full relationship cardinality

**Class:** ARCHITECTURE DECISION REQUIRED  
**Affected criteria:** AC-02–AC-05, AC-10, AC-14, AC-20, AC-21

**Observation:** Polymorphic surfaces now FK to `registry_subject.subject_id`, which is an improvement. The model and pipeline still leave duplicate native identifiers (`native_id` and legacy-added `subject_native_id`) and do not enforce that the declared native row exists in the entity table named by `subject_entity`. The subject-link trigger checks only that the subject row exists and is in an allowed state.

The object-cardinality trigger prevents only a second current `primary-subject`. It does not enforce the complete record-type/object-role matrix, subject entity compatibility, minimum required roles, role maximums, or relationship behavior during retirement/merge. The official-name trigger enforces one current Spanish official name but not the complete multilingual/current/history policy.

**Risk/consequence:** A valid subject row can still represent a nonexistent or mismatched native entity; invalid object roles and incomplete record compositions can satisfy the schema.

**Required resolution:** Normalize to one native identifier. Define and implement a subject-registration contract that verifies subject entity, native table and native ID, including creation, merge, retirement, and delete policy. Render the full record-type/object-role cardinality matrix into data-driven constraint/trigger logic. Add positive and negative tests for wrong native entity, nonexistent native row, missing required role, excessive role count, invalid role/entity pairing, retired/merged subject behavior, and multilingual current-name rules.

**Disposition:** OPEN

### NLI-WO-002-F05 — Temporal exclusions exist, but chain and containment integrity does not

**Class:** BLOCKER  
**Affected criteria:** AC-07, AC-08, AC-14, AC-20

**Observation:** The design now includes useful effective/recorded exclusions and partial current indexes. `enforce_version_chain()` only rejects self-links and checks that referenced versions share the same location record. It does not require reciprocal predecessor/successor values or prevent multi-node cycles. Equivalent reciprocal/acyclic enforcement is absent for public-code aliases and geometry supersession.

The object-link “containment” constraint only checks `effective_from < effective_to`; it does not prove that the link interval is contained by the owning record version interval. Several mutable authoritative entities still have only effective time and no recorded-time version strategy.

**Risk/consequence:** Divergent chain pointers, cycles, links outside the owning version period, and incomplete historical reconstruction can pass all current checks.

**Required resolution:** Implement reciprocal, same-owner, acyclic and no-self rules for version, alias, record-relationship and geometry chains. Add true object-link interval containment against the owning version. Decide and model recorded-time history for every mutable authoritative entity or explicitly classify it as non-bitemporal. Execute positive/backdated/overlap/reciprocal/cycle negative cases in PostGIS.

**Disposition:** OPEN

### NLI-WO-002-F06 — Geometry integrity does not enforce role-to-subject or complete observation semantics

**Class:** BLOCKER  
**Affected criteria:** AC-09, AC-11, AC-14, AC-20

**Observation:** Approved geometry now has 2D, SRID, validity, selected role/type, one-current, and self-supersession checks. The subject trigger verifies only subject-row existence; it does not compare `registry_subject.subject_entity` with the allowed subject types in `role_geometry_rules`. A building-point can therefore be linked to a locality or other registered subject.

Equivalent role/type/dimensionality logic is not applied comprehensively to `geometry_observation`. Supersession rejects self-reference but not longer cycles. Promotion from an observation to canonical geometry is not constrained to an authorized decision/evidence/quality path.

**Risk/consequence:** Semantically wrong or unauthorized geometry can become accepted/current while all exact-head checks pass.

**Required resolution:** Enforce the complete role-to-subject and role-to-geometry-type matrix for observations and approved versions. Require subject/native identity compatibility, promotion decision/evidence/quality prerequisites, and same-subject/role interval consistency. Add real negative tests for wrong subject type, wrong geometry type, wrong SRID, invalid/3D geometry, duplicate current geometry, unauthorized promotion, cross-subject supersession, and multi-node supersession cycle.

**Disposition:** OPEN

### NLI-WO-002-F07 — Lifecycle graphs are explicit, but not yet authoritative workflow contracts

**Class:** REQUIRED  
**Affected criteria:** AC-07, AC-13, AC-14

**Observation:** The prior vocabulary-order generation defect is resolved. The new graph entries still use generic actor values such as `authority-owner`, a common evidence phrase, and a common visibility/appeal rule rather than the exact role, permission, institutional scope, authority, evidence, audit event and public effect required by each transition.

The graph validator checks that edge endpoints exist and rejects a short list of known-bad pairs; it does not prove reachability, intended terminality, absence of orphan states, permitted re-entry, or binding between each stateful target field and its graph. The lifecycle overwrite identified in F03 demonstrates that these graphs can be correct in isolation while unused by the actual field.

**Risk/consequence:** WO-002B implementers must still invent permissions, state guards, public behavior, and graph binding.

**Required resolution:** Bind every stateful target field to exactly one transition registry. Replace generic actors/evidence/public behavior with transition-specific permission keys, scope, authority, evidence, audit event, effective/recorded rules, external side effects, reversal/appeal, and denial behavior. Validate graph reachability, terminality, re-entry policy, field binding, and required/forbidden edges in CI.

**Disposition:** OPEN

### NLI-WO-002-F08 — Route policy extraction remains method-unsafe and role-incomplete

**Class:** BLOCKER  
**Affected criteria:** AC-10–AC-12, AC-15

**Observation:** Function-AST boundaries correctly remove the prior 80-line bleed. The resulting policy map is stored by function name and by path only, not by method plus path. Where GET/POST or GET/PATCH/DELETE share a path, the last-decorated method overwrites the path entry used by OpenAPI fallback.

The role extractor reads only `_require_role` argument index 1. Existing handlers call `_require_role(user, 'viewer', 'editor', 'admin')`, so only the first allowed role is recorded. The generated matrix consequently labels GET `/api/v1/addresses` as editor-only and GET `/api/v1/addresses/{address_id}` as admin-only, although the current handlers allow viewer/editor/admin. Logout is labelled public because it resolves and revokes a session without directly calling `_current_user`.

The committed `openapi-expected-route-policies.json` is generated from the same derived output rather than maintained as an independent expected-policy authority. Dynamic successful responses remain field-incomplete, and field classification/projection rules remain keyword-based and generic.

**Risk/consequence:** The design pack can narrow or broaden current access incorrectly, misclassify public/protected behavior, and miss breaking response-field changes while reporting complete policy coverage.

**Required resolution:** Key policies by HTTP method and path and map OpenAPI `operationId` directly to the exact handler. Capture all `_require_role` arguments, session-required operations, optional auth and any delegated policy helpers. Maintain an independently reviewed expected-policy registry and compare derived results against it. Add response-contract inventories/models for dynamic dictionaries. For every request/response/error field, record explicit classification, target projection, release prerequisite, compatibility, adapter/deprecation and test—not a keyword default.

**Disposition:** OPEN

### NLI-WO-002-F09 — The convergence and scale artefacts remain generated summaries

**Class:** REQUIRED  
**Affected criteria:** AC-17, AC-19

**Observation:** `render_convergence()` groups rows by target entity, includes only the first twelve current fields in each row, and repeats generic crosswalk, idempotency, validation, recovery and cutover language. It does not preserve the complete reviewed transformation units, grouped coordinate transforms, reference joins, authority exceptions, application-version behavior, or per-unit recovery boundaries.

Scale values are explicit but remain unsupported planning guesses without source, confidence range, baseline date, growth model, workload mix, evidence/media distribution, selectivity, capacity calculation, owner or approval state.

**Risk/consequence:** NLI-WO-002B cannot be safely decomposed, estimated, performance-tested, or approved for cutover.

**Required resolution:** Hand-author named migration units from the accepted transformation registry after F02 closes. Include every grouped source/target transform, dependency, source and target keys, crosswalk/exception schema, write owner, dual-read/write rule, app-version matrix, idempotency, conflict precedence, validation SQL/tolerance, backup/forward-recovery point, monitoring window, cutover/abort gate and retirement proof. Label each scale assumption with source, date, confidence range, horizon, workload and approving owner.

**Disposition:** OPEN

### NLI-WO-002-F10 — Scenario count improved, but scenario meaning and negative execution remain insufficient

**Class:** BLOCKER  
**Affected criteria:** AC-05, AC-08–AC-11, AC-18, AC-20

**Observation:** Seven independently namespaced datasets are now inserted in separate schema resets. They are still generated as one row for every target entity, with only a small number of per-scenario values changed. The multi-unit scenario does not create multiple units, the corrected/superseded case does not create a version chain and corrected release history, and the administrative-boundary scenario does not create old/new administrative versions and boundary histories.

Only four negative cases perform actual failing SQL: invalid subject, geometry type, self-supersession, and duplicate primary object. Temporal overlap, invalid state transition, and publication prerequisite are recorded as rejected by assigning result strings; no failing SQL or service/model transition is executed. The final report counts all seven as rejected.

**Risk/consequence:** The pipeline can claim seven positive and seven negative validations without exercising the defining national scenarios or three named safeguards.

**Required resolution:** Author seven distinct scenario fixtures, each with only relevant entities and the exact required histories/cardinalities/projections. Execute and assert every scenario separately. Replace all simulated negative results with real failing SQL or an executable transition-policy validator. Include expected public and operator outputs and verify them against release/case data.

**Disposition:** OPEN
