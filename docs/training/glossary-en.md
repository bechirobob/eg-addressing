# Training Glossary — English

This glossary standardizes user-facing training terms for the English versions of the manuals.

| Term | Meaning | Use in training |
|---|---|---|
| Address code | The public code linked to a submitted or approved location. | Use when explaining lookup, signage, proof, and tracking. |
| Activity log | A record of important actions taken in the system. | Use for operator training; explain that formal audit logs support accountability. |
| Approval lock | A control that prevents a record from moving forward until the correct authority approves it. | Use instead of release gate for training. |
| Field check | A field-team review of a submitted location or address point. | Use instead of field verification in simple procedures. |
| GPS accuracy | The estimated precision of the captured location point. | Use when teaching location capture quality. |
| Location evidence | Information that supports where a place is located, such as GPS point, field notes, and safe attachments. | Use instead of spatial evidence. |
| Login session | A user’s current signed-in access to the system. | Use instead of auth token or session token. |
| Map evidence | Map-based or coordinate-based evidence used to review a location. | Use instead of geometry evidence in training. |
| Official record | A reviewed address record managed inside the official registry workflow. | Use instead of canonical record. |
| Public release lock | A control that prevents records, certificates, signage, or exports from becoming public before approval. | Use for publication governance training. |
| Public status | Whether a record is not public, internally held, or published. | Use instead of publication state. |
| Ready for approval | A record or case is prepared for authorized review but is not automatically public. | Use instead of registry-ready. |
| Record history | The ordered history of actions and updates for a record. | Use instead of case-file timeline. |
| Reference index | Alphabetical lookup section at the end of a manual. | Required in every manual. |
| Sign user out everywhere | End all signed-in sessions for a user. | Use instead of revoke sessions. |
| Signed-in sessions | The active places where a user is logged in. | Use instead of active sessions. |
| Submitted location | A location request sent for review. | Use instead of geotag submission. |
| Table of contents | The section list at the beginning of a manual. | Required in every manual. |
| Test record | A clearly marked training or test example. | Use instead of smoke fixture or pilot fixture. |
| Training example | A fictional or controlled example used for teaching. | Use when showing exercises or screenshots. |

## Terms to avoid in public or general training manuals

Avoid these unless the audience is technical and the term is explained:

- canonical;
- registry-ready;
- mutation;
- auth token;
- session token;
- endpoint;
- schema;
- fixture;
- PostGIS;
- raw API response.
