## 1. Cómo usar este manual

Este manual es una guía de capacitación para usuarios públicos. Puede usarse en una sesión presencial, en una capacitación corta o como documento de consulta.

Lea primero las reglas de privacidad. Después avance por los módulos en orden. Cada módulo explica qué debe hacer, por qué importa, los pasos correctos y los errores que se deben evitar.

## 2. Audiencia y responsabilidades

Este manual es para:

- ciudadanos que desean enviar una ubicación para revisión;
- residentes que necesitan comprobar el estado de una solicitud;
- empresas que necesitan entender cómo se revisa una ubicación;
- personal de atención pública que ayuda a otros usuarios a completar el proceso.

Responsabilidades del usuario público:

- escribir información clara y verdadera;
- revisar que el punto de ubicación sea correcto antes de enviar;
- no publicar datos privados innecesarios;
- conservar el código o número de seguimiento;
- entender que el piloto no equivale a publicación oficial final.

## 3. Resultados de capacitación

Al terminar este manual, el usuario debe poder:

- explicar qué es una solicitud de ubicación;
- enviar una ubicación con datos claros;
- entender qué significa la precisión GPS;
- comprobar un código de dirección;
- hacer seguimiento de una solicitud;
- distinguir entre una ubicación enviada, un registro listo para aprobación y un registro oficial publicado;
- saber cuándo contactar al soporte.

## 4. Términos clave

| Término | Significado simple |
|---|---|
| Solicitud de ubicación | Información enviada por un usuario para que una ubicación sea revisada. |
| Ubicación enviada | Una solicitud que ya fue enviada al sistema y espera revisión. |
| Código de dirección | Código público usado para identificar o comprobar una ubicación. |
| Precisión GPS | Estimación de qué tan cerca está el punto capturado de la ubicación real. |
| Evidencia de ubicación | Información que ayuda a confirmar dónde está el lugar. |
| Registro oficial | Registro revisado dentro del flujo oficial. |
| Listo para aprobación | El caso está preparado para revisión autorizada, pero todavía no es público final. |
| Estado público | Indica si un registro no es público, está retenido internamente o está publicado. |
| Bloqueo de publicación pública | Control que impide publicar antes de la aprobación correspondiente. |

## 5. Reglas de privacidad y seguridad

:::warning
No escriba números completos de documentos de identidad, contraseñas, datos bancarios, información médica ni datos privados innecesarios en los campos públicos de una solicitud.
:::

Reglas básicas:

- use solamente la información necesaria para identificar la ubicación;
- no comparta el enlace de seguimiento con personas que no deban verlo;
- revise la información antes de enviar;
- no use una solicitud de ubicación para hacer denuncias no relacionadas con direcciones;
- si una ubicación involucra información sensible, pida orientación a un operador autorizado.

## 6. Módulo 1: visión general del servicio público

### Qué enseña este módulo

Este módulo explica el propósito del servicio público.

### Por qué importa

El sistema ayuda a registrar, revisar y consultar ubicaciones de forma ordenada. El objetivo es apoyar servicios públicos, entrega, planificación, atención ciudadana y verificación de direcciones.

### Qué puede hacer un usuario público

- enviar una solicitud de ubicación;
- comprobar un código de dirección;
- hacer seguimiento de una solicitud;
- reportar una corrección pública cuando la información visible necesite revisión.

### Qué no puede hacer un usuario público

- aprobar registros oficiales;
- publicar direcciones finales;
- emitir certificados oficiales;
- crear señalización física;
- ver datos privados de revisión interna.

:::callout
La revisión y aprobación pertenecen al flujo institucional. El usuario público inicia o consulta el proceso, pero no reemplaza la aprobación oficial.
:::

## 7. Módulo 2: enviar una solicitud de ubicación

### Qué enseña este módulo

Este módulo enseña cómo enviar una ubicación para revisión.

### Procedimiento paso a paso

1. Abra la página pública para registrar una ubicación.
2. Lea la advertencia de piloto controlado.
3. Seleccione o confirme la provincia correspondiente.
4. Permita la captura GPS si está disponible y es seguro hacerlo.
5. Revise el punto mostrado en el mapa.
6. Si el punto no es correcto, corrija la ubicación manualmente según las instrucciones de la página.
7. Escriba una descripción clara del lugar.
8. Añada una referencia sencilla, como edificio cercano, carretera, barrio o punto conocido.
9. Revise la precisión GPS si aparece en pantalla.
10. Envíe la solicitud solamente cuando la información sea correcta.
11. Guarde el código o número de seguimiento.

### Ejemplo de capacitación

Una persona desea registrar la entrada principal de una pequeña tienda. El usuario coloca el punto en la entrada, escribe el nombre del negocio, añade una referencia cercana y envía la solicitud. El sistema guarda la ubicación como ubicación enviada para revisión.

### Errores que se deben evitar

- colocar el punto sobre una calle diferente;
- escribir una descripción demasiado corta, como solo “mi casa”;
- enviar una ubicación sin revisar el mapa;
- poner datos privados completos en notas públicas;
- pensar que el envío ya significa publicación oficial.

## 8. Módulo 3: comprobar un código de dirección

### Qué enseña este módulo

Este módulo enseña cómo comprobar si un código de dirección tiene información pública disponible.

### Procedimiento paso a paso

1. Abra la página pública de comprobación o prueba de dirección.
2. Escriba el código exactamente como aparece.
3. Revise si el sistema reconoce el código.
4. Lea el estado público mostrado.
5. Si hay información pública disponible, confirme que corresponde al lugar esperado.
6. Si el código no aparece o no es público, no asuma que es inválido; puede estar pendiente de revisión o retenido internamente.

### Cómo leer el resultado

| Resultado | Significado |
|---|---|
| Código reconocido | El formato del código puede comprobarse. |
| Información pública disponible | Existe información publicada para consulta pública. |
| No público todavía | El caso puede estar pendiente, retenido internamente o no aprobado para publicación. |
| No encontrado | Revise si el código fue escrito correctamente. |

:::warning
Un código reconocido no siempre significa que existe un registro oficial publicado. La publicación depende de la aprobación correspondiente.
:::

## 9. Módulo 4: hacer seguimiento de una solicitud

### Qué enseña este módulo

Este módulo enseña cómo revisar el estado de una solicitud después de enviarla.

### Procedimiento paso a paso

1. Abra la página pública de seguimiento.
2. Escriba el número o código de seguimiento recibido al enviar la solicitud.
3. Lea el estado mostrado.
4. Revise si el sistema pide más información o indica que la solicitud está en revisión.
5. Si el estado no cambia durante un tiempo razonable, contacte al soporte operativo.

### Estados comunes

| Estado | Qué significa para el usuario |
|---|---|
| Enviada | La solicitud fue recibida. |
| En revisión | Un operador o equipo autorizado está revisando la información. |
| Requiere comprobación de campo | La ubicación necesita revisión adicional por personal de campo. |
| Listo para aprobación | El caso está preparado para revisión autorizada. |
| Publicado | La información pública aprobada está disponible. |
| Rechazado o cerrado | La solicitud no avanzó; revise la explicación si está disponible. |

## 10. Módulo 5: entender el estado público

### Qué enseña este módulo

Este módulo explica por qué algunas solicitudes no aparecen como información pública inmediatamente.

### Ideas principales

- Una ubicación enviada es una solicitud, no una publicación final.
- Un registro listo para aprobación sigue protegido hasta que la autoridad correspondiente lo apruebe.
- El bloqueo de publicación pública evita que información no aprobada salga al público.
- La señalización, certificados y exportaciones oficiales dependen de aprobación.

### Diferencia entre estados

| Etapa | Explicación |
|---|---|
| Ubicación enviada | El usuario envió la información. |
| Revisión interna | Operadores revisan calidad, duplicados y evidencia de ubicación. |
| Listo para aprobación | El caso puede ser revisado por una autoridad autorizada. |
| Registro oficial publicado | La información aprobada está disponible para consulta pública. |

## 11. Ejercicios prácticos

### Ejercicio 1: preparar una solicitud de ubicación

Objetivo: practicar cómo reunir información antes de enviar.

Escenario: una familia quiere enviar la ubicación de su vivienda.

Pasos:

1. Escriba una descripción clara del lugar.
2. Identifique una referencia cercana.
3. Explique qué información no debe escribirse en notas públicas.
4. Revise qué significa la precisión GPS.

Resultado esperado: el participante puede preparar una solicitud clara sin incluir datos privados innecesarios.

### Ejercicio 2: comprobar un código

Objetivo: practicar la lectura de un resultado de comprobación.

Escenario: una empresa recibe un código de dirección y desea comprobarlo.

Pasos:

1. Escriba el código en la página de comprobación.
2. Lea el estado público.
3. Explique si el código está publicado o si puede estar pendiente.
4. Indique qué hacer si no aparece.

Resultado esperado: el participante no confunde código reconocido con publicación oficial final.

### Ejercicio 3: seguimiento responsable

Objetivo: practicar seguimiento sin exponer información privada.

Escenario: una persona quiere preguntar por el estado de su solicitud.

Pasos:

1. Use el número de seguimiento.
2. Lea el estado.
3. Prepare una pregunta breve para soporte si necesita ayuda.
4. Evite incluir datos privados completos.

Resultado esperado: el participante sabe pedir ayuda de forma segura.

## 12. Errores comunes

| Error | Por qué causa problemas | Forma correcta |
|---|---|---|
| Enviar el punto sin revisar el mapa | Puede ubicar el registro en el lugar equivocado. | Confirmar el punto antes de enviar. |
| Escribir notas vagas | Dificulta la revisión. | Usar referencias claras y verificables. |
| Incluir datos privados completos | Aumenta el riesgo de exposición. | Usar solo información necesaria. |
| Pensar que la solicitud ya es oficial | Confunde el proceso público. | Esperar revisión y aprobación. |
| Compartir seguimiento sin control | Puede exponer información de la solicitud. | Compartir solo con personas autorizadas. |

## 13. Solución de problemas

| Problema | Qué hacer |
|---|---|
| El GPS no funciona | Intente nuevamente en un lugar abierto o use la corrección manual si está disponible. |
| El punto aparece lejos del lugar real | Mueva el punto manualmente antes de enviar. |
| El código no se reconoce | Revise letras, números y guiones. |
| La solicitud no aparece | Confirme el número de seguimiento y vuelva a intentar. |
| El estado no cambia | Contacte al soporte operativo con el número de seguimiento. |
| La información pública parece incorrecta | Use el flujo de corrección pública si está disponible. |

## 16. Soporte y contacto

Para ayuda durante el piloto controlado, contacte al equipo de soporte operativo indicado por BeCore o por la institución responsable de la capacitación.

Al pedir ayuda, incluya:

- número o código de seguimiento, si lo tiene;
- descripción breve del problema;
- captura o explicación del mensaje visto, sin contraseñas ni datos privados completos;
- provincia o zona general relacionada con la solicitud.

:::callout
Este manual no reemplaza instrucciones oficiales futuras. Si la institución responsable emite una norma o procedimiento actualizado, esa norma tiene prioridad.
:::
