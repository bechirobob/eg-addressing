## 1. How to use this manual

This manual is a training guide for public users. It can be used in an in-person session, a short training class, or as a reference document.

Read the privacy rules first. Then move through the modules in order. Each module explains what to do, why it matters, the correct steps, and mistakes to avoid.

## 2. Audience and responsibilities

This manual is for:

- citizens who want to submit a location for review;
- residents who need to check the status of a request;
- businesses that need to understand how a location is reviewed;
- public-service staff who help other users complete the process.

Public user responsibilities:

- write clear and truthful information;
- check that the location point is correct before submitting;
- avoid publishing unnecessary private data;
- keep the tracking code or reference number;
- understand that the pilot is not the same as final official publication.

## 3. Training outcomes

By the end of this manual, the user should be able to:

- explain what a location request is;
- submit a location with clear information;
- understand what GPS accuracy means;
- check an address code;
- track a request;
- distinguish between a submitted location, a record ready for approval, and a published official record;
- know when to contact support.

## 4. Key terms

| Term | Simple meaning |
|---|---|
| Location request | Information submitted by a user so a location can be reviewed. |
| Submitted location | A request that has been sent to the system and is waiting for review. |
| Address code | A public code used to identify or check a location. |
| GPS accuracy | An estimate of how close the captured point is to the real location. |
| Location evidence | Information that helps confirm where the place is located. |
| Official record | A reviewed record inside the official registry workflow. |
| Ready for approval | The case is prepared for authorized review, but is not final public information yet. |
| Public status | Shows whether a record is not public, held internally, or published. |
| Public release lock | A control that prevents publication before the correct approval. |

## 5. Privacy and safety rules

:::warning
Do not write full identity-document numbers, passwords, bank details, medical information, or unnecessary private data in public request fields.
:::

Basic rules:

- use only the information needed to identify the location;
- do not share the tracking link with people who should not see it;
- review information before submitting;
- do not use a location request for complaints unrelated to addressing;
- if a location involves sensitive information, ask an authorized operator for guidance.

## 6. Module 1: public service overview

### What this module teaches

This module explains the purpose of the public service.

### Why it matters

The system helps record, review, and check locations in an organized way. Its purpose is to support public services, delivery, planning, citizen service, and address verification.

### What a public user can do

- submit a location request;
- check an address code;
- track a request;
- report a public correction when visible information needs review.

### What a public user cannot do

- approve official records;
- publish final addresses;
- issue official certificates;
- create physical signage;
- view private internal review data.

:::callout
Review and approval belong to the institutional workflow. The public user starts or checks the process, but does not replace official approval.
:::

## 7. Module 2: submit a location request

### What this module teaches

This module teaches how to submit a location for review.

### Step-by-step procedure

1. Open the public page for registering a location.
2. Read the controlled-pilot notice.
3. Select or confirm the correct province.
4. Allow GPS capture if it is available and safe to use.
5. Check the point shown on the map.
6. If the point is not correct, correct the location manually according to the page instructions.
7. Write a clear description of the place.
8. Add a simple reference, such as a nearby building, road, neighborhood, or known landmark.
9. Review the GPS accuracy if it appears on the screen.
10. Submit the request only when the information is correct.
11. Save the code or tracking number.

### Training example

A person wants to register the main entrance of a small shop. The user places the point on the entrance, writes the business name, adds a nearby reference, and submits the request. The system stores the information as a submitted location for review.

### Mistakes to avoid

- placing the point on a different road;
- writing a description that is too short, such as only “my house”;
- submitting a location without checking the map;
- putting full private data in public notes;
- thinking that submission already means official publication.

## 8. Module 3: check an address code

### What this module teaches

This module teaches how to check whether an address code has public information available.

### Step-by-step procedure

1. Open the public address check or public proof page.
2. Type the code exactly as it appears.
3. Check whether the system recognizes the code.
4. Read the public status shown.
5. If public information is available, confirm that it matches the expected place.
6. If the code does not appear or is not public, do not assume it is invalid; it may be pending review or held internally.

### How to read the result

| Result | Meaning |
|---|---|
| Code recognized | The code format can be checked. |
| Public information available | Approved public information exists for public viewing. |
| Not public yet | The case may be pending, held internally, or not approved for publication. |
| Not found | Check whether the code was typed correctly. |

:::warning
A recognized code does not always mean there is a published official record. Publication depends on the correct approval.
:::

## 9. Module 4: track a request

### What this module teaches

This module teaches how to review the status of a request after submitting it.

### Step-by-step procedure

1. Open the public tracking page.
2. Type the tracking number or code received after submission.
3. Read the status shown.
4. Check whether the system asks for more information or shows that the request is under review.
5. If the status does not change after a reasonable time, contact operational support.

### Common statuses

| Status | What it means for the user |
|---|---|
| Submitted | The request was received. |
| Under review | An authorized operator or team is reviewing the information. |
| Needs field check | The location needs additional review by field staff. |
| Ready for approval | The case is prepared for authorized review. |
| Published | Approved public information is available. |
| Rejected or closed | The request did not move forward; review the explanation if one is available. |

## 10. Module 5: understand public status

### What this module teaches

This module explains why some requests do not appear as public information immediately.

### Main ideas

- A submitted location is a request, not a final publication.
- A record ready for approval remains protected until the correct authority approves it.
- The public release lock prevents unapproved information from becoming public.
- Signage, certificates, and official exports depend on approval.

### Difference between stages

| Stage | Explanation |
|---|---|
| Submitted location | The user submitted the information. |
| Internal review | Operators review quality, duplicates, and location evidence. |
| Ready for approval | The case can be reviewed by an authorized authority. |
| Published official record | Approved information is available for public viewing. |

## 11. Practice exercises

### Exercise 1: prepare a location request

Goal: practice gathering information before submitting.

Scenario: a family wants to submit the location of their home.

Steps:

1. Write a clear description of the place.
2. Identify a nearby reference.
3. Explain what information should not be written in public notes.
4. Review what GPS accuracy means.

Expected result: the participant can prepare a clear request without adding unnecessary private data.

### Exercise 2: check a code

Goal: practice reading a check result.

Scenario: a business receives an address code and wants to check it.

Steps:

1. Type the code on the check page.
2. Read the public status.
3. Explain whether the code is published or may still be pending.
4. State what to do if it does not appear.

Expected result: the participant does not confuse code recognition with final official publication.

### Exercise 3: responsible tracking

Goal: practice tracking without exposing private information.

Scenario: a person wants to ask about the status of their request.

Steps:

1. Use the tracking number.
2. Read the status.
3. Prepare a short support question if help is needed.
4. Avoid including full private data.

Expected result: the participant knows how to ask for help safely.

## 12. Common mistakes

| Mistake | Why it causes problems | Correct approach |
|---|---|---|
| Submitting the point without checking the map | It can place the record in the wrong location. | Confirm the point before submitting. |
| Writing vague notes | It makes review harder. | Use clear and verifiable references. |
| Including full private data | It increases exposure risk. | Use only necessary information. |
| Thinking the request is already official | It confuses the public process. | Wait for review and approval. |
| Sharing tracking details without control | It may expose request information. | Share only with authorized people. |

## 13. Troubleshooting

| Problem | What to do |
|---|---|
| GPS does not work | Try again in an open area or use manual correction if available. |
| The point appears far from the real place | Move the point manually before submitting. |
| The code is not recognized | Check letters, numbers, and hyphens. |
| The request does not appear | Confirm the tracking number and try again. |
| The status does not change | Contact operational support with the tracking number. |
| Public information appears incorrect | Use the public correction workflow if it is available. |

## 14. Assessment checklist

The participant can:

- explain what a location request is;
- submit a request with a clear description;
- check a map point before submitting;
- explain GPS accuracy in simple words;
- check an address code;
- track a request;
- distinguish between submitted, ready for approval, and published;
- avoid placing full private data in public notes;
- know when to contact support.

## 16. Support and contact

For help during the controlled pilot, contact the operational support team indicated by BeCore or by the institution responsible for the training.

When asking for help, include:

- tracking number or code, if available;
- a short description of the problem;
- a screenshot or explanation of the message seen, without passwords or full private data;
- the province or general area related to the request.
